# MIDI controller support for Synthia

Research date: 2026-11-11. Status: research only, no code.

Every claim comes from a page, PDF, TXT or API response fetched on that date; anything else is marked UNVERIFIED (U-numbers refer to the lists at the end). The lead re-checked three decisive points:
- Chrome's blog: "the entire Web MIDI API is now gated behind a permission prompt … starting in Chrome 124".
- Firefox bug 1802149 ("Add hot-plug support for MIDI devices") is still NEW.
- Two controller protocols: the Twister's native-mode turns send 63/65, and the APC mini mk2 sets LED behaviour through the Note On channel byte.

Not repeated here: browser support and the webmidi.js package from docs/research/libraries.md §8.

**The requirement:** the major controllers below get ready-made profiles. Everything else works through generic handling: any keyboard plays notes out of the box, and MIDI learn covers any knob, fader or pad.

| MPE | none in `src/` (grep) | listed in README features | UNVERIFIED |

Verdict (my judgement, not a source): our needs are CC, NRPN/RPN, 14-bit CC, relative encoders, clock in/out and a few per-device quirks. Native API plus about 150 lines of our own parser is smaller than either wrapper and keeps TS types ours. webmidi earns its place only if we want its typed event model and NRPN helpers for free (13.8 KB gzip is cheap); it does not fix Firefox hot-plug (that is a browser bug) and has no MPE. JZZ is heavier, its draw is MPE/UMP/SMF, which we mostly do not need (SMF is covered by `@tonejs/midi`).

## 2. Controller families and what each sends

| Family | What a profile / the app must handle |
|---|---|
| Keyboards | Note On/Off (Note On vel 0 = Off, [LK4]); keybed, pad, pitch and mod wheel, sustain pedal all arrive on the main MIDI port ([MPK4]); pad poly aftertouch only when enabled on the device ([LK4]); pitch bend = status `En`, 2 data bytes, little-endian ([Mixxx]). CC1 / CC64 / CC11 numbers, channel pressure, expression pedal: standard MIDI, no fetched page states them (U2). Many boards add a 2nd/3rd USB port for DAW/plugin control ([MPK4]: MIDI, DAW, Plugin, Software Control, DIN; [LK4]: MIDI + DAW) - the app must pick the performance port, not the DAW port. |
| Pad controllers | Notes by default (Push 2: notes 36-99, velocity curve applied, [Push2]); can be switched to CC or Program Change per pad mode ([MPK4]: Notes / CC# / Prog Change, bank A/B). Pressure: channel pressure or poly aftertouch, selectable by SysEx on Push 2 (0x1E, default channel pressure, [Push2]) and optional on Launchkey ([LK4]). |
| Knob / fader boxes | Absolute CC 0-127 by default (Launchkey encoders and faders on ch16, [LK4]; LCXL3 [LCXL3]). Relative encodings seen: (a) offset-64: 64 = still, 65 = +1, 63 = -1 ([LK4], [LCXL3], [Mixxx] SelectKnob centre 64); (b) 63/65 only = -1/+1 ([Mixxx] Rot64, [MFT] twist); (c) two's complement ([Push2] encoders); (d) sign bit: bit 6 = direction, low bits = ticks (Mackie V-Pot `B0 1i 01` = +1, `B0 17 47` = -7, [LogicCtl]). 14-bit: two CC messages (MSB + LSB) combined to 16384 values ([Mixxx] fourteen-bit-lsb/msb) or pitch bend (`En`, 14 bit). Detection of which encoding a device uses is not in any fetched spec: the profile must declare it. |
| Transport buttons | CC or Note per device. Launchkey standalone: DAW buttons send CC on ch16; Start/Stop send MIDI Real Time Start/Stop ([LK4]). Akai MPK/MPD "MMC" mode sends `F0 7F 7F 06 xx F7` (xx: 05 <<, 04 >>, 01 stop, 02 play, 06 rec) plus MIDI Clock `F8`; "MIDI" mode sends Song Position Pointer; "CTRL" mode is CC ([AkaiTx], MPK49/MPD32 era). |
| Grid controllers with LED feedback | Pad press = Note On (Launchpad/APC/Push). LED set by Note On or CC, velocity = index into a fixed palette: Launchkey MK4 ch1 static / ch2 flash / ch3 pulse ([LK4]); APC mini mk2 and Key 25 mk2: channel selects behaviour (90h-96h = 10%-100% brightness, 97h-9Ah pulse, 9Bh-9Fh blink), velocity = 128-colour palette ([APCKey2]); Push 2 palette is rewritable by SysEx 0x03 + reapply 0x05 ([Push2]). Exact RGB: SysEx - Launchkey MK4 `F0 00 20 29 02 14 01 43 <pad> R G B F7` (Mini: `13`), Launchpad Pro MK3 SysEx `03` with up to 106 colour specs, types static/flash/pulse/RGB ([LPP3]), Twister `F0 00 01 79 06 01 01 <knob> RR GG BB F7` ([MFT]). RGB values are 0-127. |
| DAW control surfaces | Mackie Control: faders are pitch bend `E0..E8` (ch1-8 + master), top 10 of 14 bits used; buttons Note On `7F`/`00`; LEDs Note On `7F` on / `00` off / `01` flash; V-Pot `B0 10-17` relative sign-bit; V-Pot ring `B0 30-37`; jog `B0 3C`; LCD text SysEx `F0 00 00 66 <model> 12 <offset> <ASCII..> F7`, offset 00-37 upper line, 38-6F lower, 7 chars per channel; Logic Control model byte 10, XT 11 ([LogicCtl]). X-Touch needs "MC" mode for MCU use ([DBM] Mackie-MCU). HUI: no official public spec; reverse-engineered header `F0 00 00 66 05 00` (third-party PDF forum.bome.com, U3). Mackie Control Universal model byte (0x14) and handshake: U4. |

## 4. How other software maps controllers

### Mapping patterns

| Pattern | How others do it | Source |

### Hard limits of browsers

- **Safari** has no Web MIDI.
- **Firefox:**
  - Needs a site-permission add-on.
  - Never fires hot-plug events, so users must rescan or reload after plugging in.
  - Has no MIDI on Android.
- **Chrome:**
  - Prompts for any MIDI use, and SysEx is a second, stronger prompt.
  - Has no `MIDIOutput.clear()`, so queued notes can't be cancelled. Keep scheduling to the conductor's ~100 ms lookahead and send note-offs or CC 123 by hand.
  - Has no MIDI in workers yet.
- **Every browser:**
  - `send()` has no backpressure signal.
  - Timestamps use the `performance.now()` clock, not audio time.
  - BLE MIDI works only where the OS pairs it (macOS yes; Windows is preview-only; others UNVERIFIED).
  - There is no MIDI 2.0.
  - Push displays and NI light guides are out of reach.

## Decisions (settled 2026-11-11)

1. **SysEx:** ask lazily, only when a connected profile needs it (Launchpad programmer mode, Launchkey RGB pads and screen, Twister native mode), and only after our own plain-language explainer. APC grids and X-Touch Mini rings work without it.
2. **Library:** native Web MIDI plus our own small parser. No webmidi.js.
3. **Browsers:** Chrome only, which is already the decision for the whole app. The Firefox and Safari limits above are kept for reference.
4. **Profiles** are JSON. An "export my mapping" button turns a learned mapping into a profile, and plugins can add profiles. The project lead is asking the owner which controllers they own, because several phase 1 defaults are unpublished.
5. **Profile data:** we write our own profiles from vendor documentation; nothing is copied from GPL (Mixxx, Ardour) or proprietary (Ableton) scripts. Their licence follows whatever licence the repository gets.
